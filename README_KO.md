# CGV 용산 IMAX 〈듄: 파트 3〉 시간표 감시 v1.2 (Docker 배포 오류 수정)

## v1.2 긴급 수정 사항 (2026-11-25)

- **해결:** v1.1에 포함된 `failure_policy.mjs`를 Dockerfile이 복사하지 않아 Railway에서 `ERR_MODULE_NOT_FOUND`로 반복 Crash가 발생했습니다. Dockerfile의 `COPY *.mjs ./`로 보완했습니다.
- **예방:** `verify_local_imports.mjs`를 컨테이너 빌드 중 실행하여 앞으로 누락된 상대경로 모듈이 있으면 **배포되기 전에 빌드를 실패**시키도록 했습니다.
- 기존 v1.1의 감시 조건 및 HTTP 502 오류 대응 로직은 그대로 유지합니다. **이 수정은 CGV Relay HTTP 502 자체를 해결하는 수정은 아닙니다.**
- GitHub에는 이 ZIP 내부 파일 전체를 **최상위 경로**에 덮어쓰세요. 특히 `Dockerfile`, `failure_policy.mjs`, `verify_local_imports.mjs`가 모두 존재해야 합니다.

## 먼저 읽어 주세요

2026-11-25 Railway 로그에서 **2026-12-20은 relay로 듄3 IMAX 7회차 조회 성공**하지만, **2026-12-21/22는 relay HTTP 502, CGV 직접 HTTP 403**이 반복되었습니다. 따라서 **정상 신규 날짜 감시가 입증되지 않았습니다.** 이 패키지는 오류 판단·재시도 로직을 바로잡은 버전이며, **Relay가 실제로 신규 날짜의 시간표를 전달하지 못하는 동안에는 예매 오픈을 감지할 수 없습니다.**

CGV 접근 제한을 우회하는 기능은 넣지 않았습니다. 403/429가 현재 사용 중인 조회 경로에서 반환되면 반복 요청하지 않고 종료합니다. 보조 직접 조회는 기본 비활성화합니다.

## 고친 부분

1. 12/20 기준일 조회가 성공해도 **12/21 이후 감시 대상의 실패 횟수를 초기화하지 않습니다.** 과거 v1의 오류 관리 버그 수정.
2. relay 502와 CGV 403 HTML 본문을 텔레그램에 길게 붙이지 않고 **`Relay: HTTP 502` 등으로 짧게 안내**합니다.
3. CGV 직접 조회는 Railway에서 403을 반환하므로 기본 비활성화(`ENABLE_DIRECT_FALLBACK=false`). Relay가 502인 경우 타깃 날짜는 **조회 불가/미확인**으로 유지되며 **미오픈으로 확정하지 않습니다**.
4. 정상 조회 상태에서는 5~7초 랜덤 주기(단, 서버·캐시 지연 가능), 오류 시에는 60~90초 주기로 완화합니다. Relay 502가 오래 지속된다면 수분 이상 감시가 불완전할 수 있습니다.
5. 대상 날짜 조회가 실제 정상 복구되면 텔레그램으로 복구 알림을 보내고, 이미 발견한 회차는 중복 알림을 억제합니다.
6. Relay가 실제로 `403`/`429`를 반환한다면 접근 제한으로 판단해 종료합니다. 자동 차단 우회 없음.

## 기본 대상

- 영화 번호 `30001790`, CGV 용산아이파크몰 `0013`, IMAX만.
- 2026-12-16~20은 이미 열린 날짜라 제외, **2026-12-21부터 2027-01-10**까지.
- 새 상영 날짜/회차 발견 시 텔레그램 메시지 및 CGV 예매 링크만 보냅니다.
- 로그인/좌석선점/자동예매/결제 기능은 없습니다.

## Railway 배포

1. 압축 해제 후 내부 파일을 기존 CGV 듄3 GitHub 저장소의 루트에 덮어쓰고 commit 합니다.
2. Railway의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`는 그대로 사용합니다. `/data` volume도 있으면 유지합니다.
3. 이전에 `DIRECT_URL` 환경변수를 설정해 두었어도 이제 **`ENABLE_DIRECT_FALLBACK=false`(기본값)**인 한 직접 조회하지 않습니다.
4. `POLL_MIN_SECONDS=5`, `POLL_MAX_SECONDS=7` 기본 유지. 오류 발생 시 `ERROR_POLL_MIN_SECONDS=60`, `ERROR_POLL_MAX_SECONDS=90`이 적용됩니다.
5. `ERROR_ALERT_COOLDOWN_SECONDS=1800`, `BASELINE_RECHECK_MINUTES=15` 기본값입니다.
6. Deploy Logs에 `CGV 용산 IMAX 듄 파트3 오픈 감시 v1.2`가 표시되는지 확인하세요.

### 로그 판정

- `기준일 20261220 검증 성공`은 **Relay 일부 날짜 데이터가 작동한다는 뜻일 뿐, 12/21 감시가 정상이라는 뜻이 아닙니다.**
- `조회불가 20261221: 상태=UPSTREAM_UNAVAILABLE, Relay: HTTP 502`면 **오픈 여부 미확인**입니다. 감시 성공 아님.
- `20261221: 정상 API 응답, 듄3 IMAX 신규 회차 0건`이면 해당 요청이 JSON으로 정상 반환되었지만 목표 영화의 IMAX 회차가 없다는 뜻입니다. 실제 예매 페이지와 동기화되었는지는 별도 확인해야 합니다.
- `OPEN 20261221`이면 새 IMAX 상영 회차를 확인했고 Telegram 알림을 시도했습니다.

## 현실적인 대체 알림

이 코드의 소스가 12/21 이후에서도 502를 계속 반환한다면, 다음 대안은 정상 조회 경로가 입증되기 전까지 더 많은 코드 수정으로 해결할 수 없습니다. CGV 공식 SVIP 오픈 알림이나 기존 용산 IMAX 공개 Telegram/Discord 알림 서비스 등을 병행하세요. 타사 서비스의 동작 여부·지연은 별도로 확인해야 합니다.
